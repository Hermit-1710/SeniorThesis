# CTRestormer

`CTRestormer` is the main Transformer denoising model for this repo.

It is a Restormer-style multi-scale image restoration transformer adapted for low-dose CT denoising.

## Design goals

- keep the model fully transformer-based in the main feature hierarchy
- preserve local detail better than the current shallow CTformer
- provide stronger global context than pure CNN baselines
- remain trainable on an RTX 3060 Laptop GPU with `64x64` patches

## Architecture

Input patch size in the default training setup:

- `1 x 64 x 64`

Feature pipeline:

1. overlap patch embedding: `1 -> 32`
2. encoder level 1: `32 x 64 x 64`
3. downsample to level 2: `64 x 32 x 32`
4. encoder level 2: `64 x 32 x 32`
5. downsample to level 3: `128 x 16 x 16`
6. encoder level 3: `128 x 16 x 16`
7. downsample to latent: `256 x 8 x 8`
8. latent transformer blocks: `256 x 8 x 8`
9. decoder level 3 with skip fusion
10. decoder level 2 with skip fusion
11. decoder level 1 with skip fusion
12. refinement transformer blocks
13. residual image prediction: `output + input`

Default recommended configuration for an RTX 3060 Laptop GPU:

- base dim: `24`
- encoder/latent blocks: `(1, 2, 2, 3)`
- refinement blocks: `1`
- heads: `(1, 2, 4, 4)`
- batch size: `2`
- gradient accumulation: `2`
- AMP: `on`

## Transformer block

Each block contains:

1. `LayerNorm2d`
2. `MDTA` attention
3. residual connection
4. `LayerNorm2d`
5. `GDFN/FFN` feed-forward branch
6. residual connection

## Attention choice

The attention module is `MDTA`:

- query, key, value generated by `1x1` convolution
- local mixing added by depthwise `3x3` convolution
- channel-normalized attention
- multi-head feature interaction

This gives a better image restoration bias than a plain ViT block.

## Training recipe

Recommended first training recipe:

- optimizer: `AdamW`
- learning rate: `2e-4`
- weight decay: `1e-4`
- scheduler: `CosineAnnealingLR`
- loss: `HybridLoss = 0.8 * Charbonnier + 0.2 * SSIM`
- batch size: `2`
- gradient accumulation: `2`
- AMP mixed precision: `enabled`
- patch size: `64`
- patch count per slice: `4`
- test patient: `L506`

## Why this should beat the current CTformer

The local CTformer implementation is currently very shallow and acts more like a lightweight token mixer.

`CTRestormer` is stronger because it has:

- deeper transformer hierarchy
- true multi-scale encoder-decoder structure
- skip-connected reconstruction path
- image restoration oriented attention
- more expressive latent representation

## Expected outcome

Compared with the current local CTformer:

- likely gain: `+0.4` to `+1.0 dB` PSNR
- likely gain: `+0.004` to `+0.012` SSIM

Compared with the current local RED-CNN:

- realistic target: match or slightly exceed it
- likely gain range: `0.0` to `+0.5 dB` PSNR if convergence is good
